LAT AI — исправление позднего завершения SDK, 11.11.2026

Причина прежнего сбоя: AbortSignal.timeout(120000) продолжал существовать после
завершения load. SDK2.1.0 сохранял обработчик abort, который посылал cancel
в уже закрытый transport. Стек и предупреждения прошлого запуска сохранены.

Исправление в локальном диагностическом коде: loadWithDeadline создаёт свой
AbortController и таймер, затем снимает таймер в finally после успеха/ошибки load.
Не обновляли LM Studio/SDK, не патчили установленную библиотеку, не меняли модель.
Исторический замороженный скрипт, завершившийся с ошибкой, оставлен как доказательство.
Новый исполняемый пример: tools/verify-sdk-deadline-live.mjs.

Проверки
-4 unit tests: отсутствие позднего abort после успеха и ошибки, один abort при
 зависшей загрузке без повторов, запрет подмены управляемого signal вызывающим кодом.
-Живой заранее замороженный протокол:2 собственные загрузки Qwen3.5-9b через helper,
 checkpoints32 и0; по одному известному V11; всего4 terminal model POST.
-REST и SDK config проверены; обе оценки завершились. Это технический smoke,
 не новый holdout и не дополнительная проверка качества на учениках.
-Оба экземпляра выгружены с доказательством; обе блокировки штатно освобождены.
-Общий SDK client закрыт. Процесс намеренно оставался жив до срока последнего
 load_started +120000+3000мс, то есть после обоих прежних сроков автоматического abort.
-Exit0, summary.complete=true, предупреждений channelUnknown и исключения
 disposed transport нет. Новый GET подтвердил отсутствие обоих instance ID.

Ограничения
Это две успешные живые загрузки и отдельные unit tests, не гарантия поведения при
любом сбое сети/загрузки. Истинный live load timeout не вызывался намеренно.
Unknown не повторялся, старый диагностический lock не удалялся.
Исправление не меняет оценивание: два прохода той же модели могут одинаково ошибаться.

Доказательства: sdk-live-protocol.json +SHA, sdk-live.log, sdk-live/*,
sdk-unit-tests.log, sdk-process-proof.json. Скрипт и helper зафиксированы в протоколе.
Frozen128 использует прежний CLI loader и запускается с неизменённым планом;
SDK helper в этот ранее замороженный runner не подставляется.
