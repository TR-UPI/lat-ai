LAT AI — как проверить advisory-only сигналы после реального пилота

1. Координатор «разраб 1 П» назначает двух действительно разных слепых разметчиков
   и третьего участника для споров. Начало сбора по прежнему плану12.11.2026.
   Использовать уникальные постоянные IDs; пробелы/регистр не создают новую личность.
2. Реальные обезличенные работы и разметки заморозить prepare-shadow-pilot.py.
   Новая версия отклонит adjudicator, совпадающего с одним из разметчиков, а также
   пустую причину спора. Сохраняются первоначальные мнения и отдельное решение.
3. Выполнить обычный frozen runner v2 по заранее утверждённым трём порядкам.
   Первичная серия1, модельный план/рубрики не подбирать по результатам сигналов.
4. После трёх complete/retirement_proven серий выполнить:
   python tools/review-signal-pilot.py analyze SIGNAL_PROTOCOL MODEL_PLAN RUN1 RUN2 RUN3 NODE_EXE NEW_OUTPUT
   SIGNAL_PROTOCOL: outputs/review-signals-prototype-2026-11-11/signal-protocol.json
   NODE_EXE для этогоПК: work/lat-ai-runtime/node/node.exe
   Перед запуском protocol/SHA и все зависимости должны совпасть. При переносе
   сохранить структуру tools и lat-ai/integration/ai/core; Python — stdlib.
5. review-queue.json предназначен координатору/преподавателю ПОСЛЕ первичной слепой
   разметки, а не исходным слепым разметчикам. В нём есть модельные/человеческие метки.
   Заполнить teacher_decision,teacher_reason,reviewed_by в отдельной рабочей копии.
6. Сопоставить workload, пропущенные ошибки и ложные тревоги по первичной серии.
   Не считать отсутствие сигнала основанием автоматически выдать балл.

Производственный gate и баллы не меняются. Runtime prototype не интегрирован в UI.
Нужен новый отдельный протокол и решение людей до любого применения к ученикам.
Текущие unit/e2e tests не заменяют реального пилота. На known128 этот exporter
целенаправленно отказывает: data_origin=synthetic_smoke, а не real_student.
