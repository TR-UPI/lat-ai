LAT AI — изменение будущего плана пилота, 11.11.2026
Координатор: разраб 1 П. Плановое начало сбора: 12.11.2026.
Реальных ответов, двух независимых разметчиков и решений по спорным случаям нет.

До результатов зафиксировать объём, задачи, правила включения/исключения,
разметчиков и третьего человека для споров, пороги ошибок и отказов, порядок
обезличивания, доступа и срок хранения. Предыдущие 80 работ/2–3 задачи и пороги
остаются предложением, а не утверждённым допуском. Теневые оценки ученикам не выдаются.

Дополнительно зафиксировать:
1. SHA весов, выбранную версию runtime/CLI, GPU/драйвер, AI source SHA, конфигурацию
   загрузки, seed для генерации порядка. Настройки не подбирать после результатов.
2. Три разных порядка одних и тех же работ; первичная серия всегда первая.
   Новый инструмент v2 хранит порядки в плане; файлы старой заморозки не переписывает.
3. Новая собственная загрузка перед каждой серией, без дополнительных прогревов;
   одинаковые настройки всех трёх серий. Model ID и все предшествующие запросы записываются.
4. Различать «свежая серия» и «свежая модель перед каждым ответом». В текущем v2
   только первый ответ серии обрабатывается свежей моделью. Проверка cold/warm
   каждого ответа требует отдельного протокола и здесь не обещается.
5. Для каждого ответа считать распределение исходов, изменения критериев и цитат.
   Три вызова одного ответа не увеличивают независимый размер выборки втрое.
6. При unknown не повторять POST; при изменении окружения/кода/порядка либо
   неподтверждённой выгрузке остановить серию и сохранить незавершённый результат.

Новый v2 прошёл 17 технических тестов, включая сквозной тест с заглушкой.
Живой скан 128 известных авторских ответов заморожен, но НЕ запущен после аварии
завершения SDK в отдельном опыте. Это не результат пилота и не доказательство
доли чувствительных ответов. Прежний v1 оставлен для проверки старых артефактов.

Политика «только неполный балл отправлять человеку» не включена: текущие данные
не доказывают безопасность всех полных оценок. Решение по процессу рассмотрения
отказов и предварительных оценок принимает координатор с преподавателем;
передавать его backend/frontend-разработчикам отдельно. Gate и UI не менялись.

Третий независимый судья и детерминированные сигналы для ручной очереди пока
не реализованы. Не считать две инструкции одной модели независимыми судьями.
