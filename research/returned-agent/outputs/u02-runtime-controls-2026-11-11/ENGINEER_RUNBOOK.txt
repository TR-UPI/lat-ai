LAT AI — будущие проверки разных порядков, инструменты v2
Только AI evaluation tooling; production prompt/rubric/gate не меняются.

1. Подготовить реальные обезличенные ответы и две слепые разметки с разрешёнными
   спорами существующим prepare-shadow-pilot.py. Не использовать known128 как пилот.
2. Создать settings JSON по known128-settings.json: выбрать реальные пути весов
   и runtime preferences, заранее задать order_seed и полную expected_load_config.
   Имя PC/конфигурация в примере относятся только к этому ПК. Пути явные, не секреты.
3. node tools/prepare-assessment-run-v2.mjs SOURCE FROZEN REVIEWED_RUBRIC SETTINGS NEW_PLAN
   План измеряет SHA файла весов, CLI, выбранный backend из локальных preferences,
   GPU/драйвер и сохраняет три разных порядка. Это не аттестация бинарника engine
   или того, что HTTP model key криптографически связан с файлом весов.
4. После штатного освобождения собственным стендом модели:
   node tools/run-frozen-assessment-v2.mjs PLAN 1 NEW_RUN1
   Повторить с 2/3 только после complete и retirement_proven предыдущей серии.
   При неполной серии не использовать новые каталоги для скрытого повтора.
5. python tools/analyze-frozen-pilot-v2.py PLAN RUN1 RUN2 RUN3 NEW_ANALYSIS
   Анализ проверяет SHA provenance, окружение до/после, разные instance ID,
   фактические позиции и цепочки запросов. Сопоставляет ответы по ID, а не позиции.
6. Вернуть штатный стенд через ai-model-control.ps1 -Action enable и проверить idle.

Официальный SDK установлен изолированно в work/u02-runtime-sdk (@lmstudio/sdk2.1.0),
только для опыта checkpoints. Runner v2 использует прежний CLI load и SDK не требует.
Зависимости проекта не менялись. Ни новые веса, ни облачная модель не загружались.

Авария SDK: AbortSignal.timeout(120000) остаётся активен после успешной загрузки.
В установленном SDK load сохраняет abort listener (dist/index.mjs:8448), который
посылает cancel. После disposal это привело к исключению transport disposed.
channelUnknown warnings в логе согласуются с отменой уже завершённых каналов;
точная роль каждого warning в inference отдельно не доказана.
Для следующего эксперимента подготовлен sdk-load-with-deadline.mjs: собственный
AbortController + clearTimeout в finally. 4 теста без модели прошли, живого подтверждения нет.
Он НЕ подставлен задним числом в замороженный diagnose-u02-checkpoints.mjs.
Не запускать старый диагностический скрипт повторно в существующие каталоги.

Последний diagnostic model.lock сохранён после аварии. Восемь выгрузок доказаны
квитанциями; последующий GET подтвердил отсутствие этих instance ID. Lock не удалять
по возрасту и не использовать его для новой загрузки. Штатный стенд имеет свой lock.

Открытая проверка специалиста: жизненный цикл SDK, независимая семантическая оценка
U02, достаточность конфигурационного эксперимента. По просьбе владельца при этом
непредвиденном завершении новые model inference остановлены; plan known128 заморожен,
но live-каталогов нет. После разбора можно запустить его отдельным этапом, без смены
промптов/порядка/первичной серии. Не объявлять результат заранее.
