LAT AI · оператору сводки ручного аудита

Запуск из корня рабочей области через work/runtime/python-env/python.exe.
Пути в примерах относительные; значения STORE/ASSIGNMENT/OUT заменить осознанно.
Не использовать скопированные TECHNICAL_FIXTURE stores как настоящие рабочие базы.
Постоянный owned_idle_barrier штатен: intake.lock не удалять. Старые prepare/receive
не использовать на store, переведённом на recovery. Не чинить неизвестный lock вручную.

1. Проверка целостности, отчёт только в новый файл:
python tools/check-ai-readiness.py check outputs/ai-readiness-and-audit-summary-2026-11-11/readiness-protocol.json NEW_READINESS.json
0 = файлы совпали, 2 = остановка. Это не проверка живого runtime и не допуск качества.

2. Явный индекс, JSON ровно с такими полями:
{
  "store_id": "UUID из STORE.json",
  "mode": "DECLARED_POST_LABEL_HUMAN_RETURN",
  "assignments": [{"path": "абсолютный путь выданной assignment-папки", "assignment_sha256": "SHA256 ASSIGNMENT.json"}]
}
Для технических примеров mode=TECHNICAL_FIXTURE. Декларация human mode не доказывает
происхождения данных; известную fixture под human mode инструмент отклоняет.
Список непустой; пути и SHA уникальны. Указывать все предназначенные для сводки выдачи,
включая ещё не вернувшиеся. Неиндексированные выдачи видны как пробел покрытия,
их внешние папки не читаются. Не подменять список выборкой только удачных возвратов.

3. Создать новый экспорт:
python tools/summarize-audit-returns.py export outputs/ai-readiness-and-audit-summary-2026-11-11/summary-protocol.json STORE INDEX.json NEW_OUT
NEW_OUT вне store и всех assignment-папок, не существовавший ранее.
SUMMARY.json содержит решения/причины/исключения, READOUT.txt — краткое чтение,
INDEX_RECEIVED.json — точный индекс, CAPTURE.json — время/хеши, MANIFEST.json — завершение.
Нет MANIFEST — это не законченный экспорт. Не собирать его вручную из частичных файлов.

4. Перед использованием проверить актуальность:
python tools/summarize-audit-returns.py verify-export outputs/ai-readiness-and-audit-summary-2026-11-11/summary-protocol.json STORE EXISTING_OUT
0 = экспорт совпадает с источниками на момент чтения; не утверждение качества.
3 = stale: сохранить старый и сделать новый экспорт в другую папку.
4 = corrupt_export: сохранить повреждённый для расследования, не исправлять байты.
2 = invalid_or_unavailable: проверить сообщение, путь, протокол и read-only triage;
не обходить ownership/locks, не повторять изменяющие операции автоматически.
Любая новая выдача, поправка или терминальная запись может сделать снимок устаревшим.
Статус не является вечным: перед решением/передачей проверку повторить.

Чтение результата
Группа = исходный render-manifest SHA + audit_id. Исходные immutable поля сверяются.
Различные ID/пакеты не объединяются по тексту; возможная зависимость отмечается.
Всегда учитывать denominators: indexed, issued_not_in_index, without_registered_return,
excluded_assignments и counts в каждой группе. Исключение не удаляет решение.
uncertain / not_selected / unreadable — не положительное согласие. Для fragment IDs
same_set не равно смысловой достаточности цитаты; список номеров должен проверить человек.
automatic_resolution=null всегда. Даже все равные поля не создают независимый gold.
Новые баллы, модельный inference, accuracy/каппа здесь не вычисляются.

Канал выдачи
Это частный инструмент координатора после завершения независимой разметки.
SUMMARY содержит все human_reason. Проверить свободный текст на персональные данные
перед передачей. Не отправлять сводку разметчикам до/во время слепой разметки.
Хранить ссылки и SHA корневых протоколов отдельно от архива; SHA внутри одного ZIP
не является доказательством подлинности. Новый протокол — новая версия, frozen не править.
