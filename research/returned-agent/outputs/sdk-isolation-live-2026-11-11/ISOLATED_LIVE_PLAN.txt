LAT AI · подготовка полноценного SDK v2 live · 11.11.2026
Статус: NOT_RUN. Это инженерный план, не готовый launcher и не разрешение по JSON.

Цель: успешная llm.load через неизменный sdk-load-with-deadline-v2, unload своего
экземпляра, dispose и жизнь клиента за исходным deadline; затем отдельный опыт
с отменой в процессе загрузки и доказательством прекращения всего собственного runtime.
Ни одного запроса к общей модели. Промпты, backend/frontend не меняются.

Чего сейчас нет
Отдельного работающего runtime с подтверждёнными данными/настройками/портом и владением.
В общей LM Studio home нет записи установки llmster. CLI daemon up может переиспользовать
уже запущенный сервер; поэтому запускать его для получения «второго runtime» нельзя.
Другой model UUID или порт того же процесса не заменяет изоляцию состояния и процессов.
Нет проверенного launcher/job-controller для такого runtime; декларативные flags не
являются доказательством. Малый embedding не заменяет проверку llm.load.

Входные условия будущего запуска (зафиксировать до dispatch)
1. Доступный отдельный runtime/хост либо подтверждённый независимый профиль процесса.
   Для Windows без документированного data-dir — подготовленный отдельный пользователь
   или VM; не подменять общий home/junction и не запускать общий daemon down.
   Этот этап не создаёт пользователей, VM, системные службы и не меняет доступ.
2. Точные версии и SHA SDK, helper, Node, runtime, весов; неизменный набор source209.
   Зафиксировать документированный способ выбора профиля и запрет fallback/discovery.
3. Запускать свой runtime через отдельный Windows job: kill-on-close, процесс создаётся
   suspended и включается в job до resume; запрет breakaway, лимит памяти, учёт потомков.
   Launcher обязан быть реализован и проверен отдельно до load. Сейчас его нет.
4. Endpoint loopback с явным портом, исходно свободным и отличным от общего.
   PID/starttime слушателя должен принадлежать созданному дереву; сверить непосредственно
   перед load/abort/cleanup. SDK получает baseUrl явно. Не использовать CLI autodiscovery.
5. Ресурсный бюджет выбрать до запуска; CPU-only для тестовой модели, без общей GPU.
   Текущий предварительный барьер: размер минимального имеющегося LLM-веса +1GiB
   запаса (3814679712 bytes). Это консервативная политика, НЕ измеренный peak и НЕ точная
   оценка памяти. Фактическая свободная память 2221633536 bytes до read-only smoke.
   Нужны измерение/оценка allocation на отдельном стенде и мониторинг RAM/job во время.
   При нехватке — остановить только собственное дерево с доказательством, общую модель
   и другие приложения не закрывать. Не считать общий model ID показателем отсутствия
   давления на память или падения производительности.
6. Сохранить общие PID+creation, loaded ID/config/load-time где доступно, настройки/
   discovery hashes до/во время/после. Без чтения credentials/чужих разговоров.
   Точечные снимки не доказывают непрерывного отсутствия изменений.

Последовательность (каждый опыт отдельный, с новым ID, без retry)
N: normal load с deadline120000ms, UUID заранее записан. Сохранить время dispatch,
   progress, resolve, handle-ID/config. Без inference достаточно lifecycle-проверки.
   Успешная однократная выгрузка своего ID, terminal acknowledgement, read-only список.
   Dispose SDK, удержание до load_started+123000ms; естественный exit процесса.
   Это подтверждает только один normal lifecycle на выбранных версии/весе/устройстве.
A: только после N и готового containment. Новый frozen subplan до запуска с timeout,
   который позволяет увидеть server load_started до abort. Если загрузка завершилась
   раньше abort — результат «отмена в процессе не достигнута», не успешный abort-test.
   Сохранять реальное исключение/тип/cause/signal state, а не искать только текст ошибки.
   Ограниченное заранее окно наблюдения (30s) по логам/GET — свидетельство, не terminal proof.
   Остановка только собственного job; signal process handles, ActiveProcesses=0,
   полное перечисление PID+creation и отсутствие слушателя. Поздняя загрузка невозможна
   только при подтверждённом прекращении всего принадлежащего опыту дерева.
   Не принимать rejection SDK или один GET без ID за серверную отмену.

Таблица исходов
— Нет доказательства изоляции/ресурсов: NOT_RUN, model dispatch0.
— Load resolve + unload terminal + post-deadline survival: normal lifecycle observed.
— SDK reject, серверный исход неизвестен: incomplete/quarantine; не повторять load/unload.
— Load завершился раньше timer: abort not exercised; не сокращать deadline по результату
  и не выдавать повтор за тот же замороженный опыт.
— Job/handle/port/identity proof неполон: quarantine; сохранить профиль и locks.
— Source/settings drift или изменение общего состояния: stop, причина неизвестна до анализа;
  не восстанавливать общую модель самостоятельно и не стирать evidence.
— Процессное дерево прекратилось: containment termination, не «SDK сам отменил сервер».

Новый freeze будет содержать реальные launch recipe/endpoint/веса/ресурсы/timeout,
а не незаполненные поля этого плана. Старые протоколы и locks не переиспользовать.
