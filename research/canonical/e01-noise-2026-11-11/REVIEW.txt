Policy and preservation findings
Only the exact two supporting kind/scope pairs can collapse, gated by explain plus the known computed_program scope/provenance marker and absence of analysis_limit. Unknown kinds/scopes, hint/unknown roles, explicitly supplied protected IDs, computed evidence, and trace records remain visible. Partitioning retains the original objects and order; the full view retains original order. Invalid fact IDs/types and unknown protected IDs reject before replacing the rendered view. The teacher notice is outside details in both columns. Native details/summary semantics are retained, and changing the selected case renders a fresh details element.

Metric findings
The reported original historical reductions are 8.1122% for fact text and 6.4563% including the notice and summary; original development reductions are 17.5594% and 14.1229%. These figures reproduce exactly under the documented calculation. The trace summaries are correctly separated as compatibility only. No new model calls, held-out evaluation, comprehension gain, latency gain, or joint trace/noise effect is established by these calculations.

Minor limits / evidence caveats
1. BROWSER_CHECK.txt candidly records that real browser validation did not run. Keyboard behavior, screen-reader announcements, narrow-screen layout, print expansion, and hostile-markup behavior in an actual browser remain unverified. The fake DOM tests do not close this gap; preserve this caveat in the package and status.
2. The character metric counts JavaScript string length (UTF-16 code units), with newline separators between fact texts. The adjusted metric adds the notice and summary only. It is not a measurement of viewport occupancy, reading time, all page UI text, or token savings. Label it accordingly when reporting.
3. Protected references are supplied explicitly through protectedIds; the renderer does not discover citations. The preview hardcodes explain because every frozen request has that role. These are acceptable boundaries for this fixed facts-only experiment, but not evidence of safe arbitrary live-response integration.
4. The presentation layer validates its consumed record fields and trusts the upstream computed_program provenance marker. It does not revalidate the analyzer's semantic completeness or the entire ledger schema. No such broader validation claim should be inferred.
