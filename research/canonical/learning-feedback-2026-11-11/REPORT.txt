1. Варианты ответа
Причина: глобальная ширина input применялась к radio. Теперь у radio фиксированный размер 18 px, у строки — две колонки, общий кликабельный label, перенос текста слева, checked/focus-состояния. Проверены desktop и узкий viewport, переключение стрелкой Down. Узкая проверка дала фактическую ширину viewport 520 CSS px и scrollWidth 500 — не заявляем отдельный реальный телефон 390 px.

2. Разбор ошибки
Новая генерация связывает {option, feedback} по точному тексту варианта, а не по позиции произвольного массива. При сохранении нормализует option_explanations[4]; общее explanation выводит из разбора верного варианта. Ошибочные/дублирующиеся/неизвестные привязки отклоняются.
До попытки публичная карточка вопроса содержит id/prompt/options. После попытки выдаётся разбор выбранного варианта и текст верного ответа. Интерфейс отдельно показывает балл, выбранный и верный варианты, объяснение. Цитата по умолчанию свёрнута; одинаковый старый feedback/quote не печатается дважды. HTML экранируется. Старые result остаются читаемыми; старые баллы не меняются.

3. Подсказки — частичный результат, качество не закрыто
Свободная генерация подсказок оказалась ненадёжной: модель повторяла вопрос, пересказывала готовый ответ, а её булевы проверки иногда это пропускали. Восемь промежуточных dev-прогонов и все неудачи сохранены; это не независимый holdout и не оценка общей частоты ошибок.
Финальный механизм исключает ОДИН неверный вариант и использует его уже проверенный модельный разбор. Остаются три варианта. Отбрасываются слишком длинный/пустой/общий текст, повтор цитаты, прямое упоминание правильного варианта (включая короткие метки). Затем отдельная модельная проверка может отклонить подсказку. Неподходящая подсказка явно недоступна; прежней общей заглушки «сравни с текстом» нет.
Важно: это разрешённая помощь с одним отрицательным ответом и его причиной до попытки. Не заявляем, что вообще никакие объяснения не раскрываются до ответа. Правильный ключ и полный массив разборов не раскрываются.
Нормальный запрос теперь содержит 4 последовательных модельных вызова: генерация, слепая проверка ключей, проверка объяснений, проверка итоговых подсказок. Один прежний бюджет 180 секунд и общий coordinator/lock; неизвестный исход не вызывает автоматического повтора. Новых весов, платного API, RAG нет.
