UX01 — четыре замечания ручной проверки

Авторизация: текущие прямые замечания владельца; стиль существующей платформы сохраняется. Отдельный редизайн платформы не нужен. Разработка в work/learning-feedback-stage/LAD-AI-Document-Pilot, затем проверенный перенос в work/lat-ai. Исходный source и четыре скриншота сохранены здесь.

1. Frontend: локализовать CSS radio/label и компактный перенос текста; selected/focus состояния. Результат MCQ: балл/статус, выбранный и верный ответы, объяснение выбранного варианта, отдельная свёрнутая цитата без дублирования. Python assessment: отдельный блок балла и критерии вместо сплошного текста. HTML escaping, клавиатура, мобильная ширина.
2. Model/backend: новые вопросы содержат option_explanations[4] в порядке options. Объяснение называет конкретную ошибку варианта и связь с подтверждённым правилом. После попытки API выдаёт только выбранный разбор + correct_option; до попытки ключи и explanations скрыты. Старый формат остаётся читаемым без пересчёта баллов. Подсказка конкретная: принцип/шаг/наводящий вопрос; без номера/готового ответа и общего «сравни с текстом». Сохранить blind key agreement и общий lock/budget; не ослаблять выставление баллов. При необходимости один ограниченный repair подсказки, никакого бесконечного model retry.
3. Проверить регрессии и новые отрицательные случаи схем, приватность, replay, старые данные. Живой синтетический SQL-тест с нормальным и ошибочным выбором; браузер на desktop/mobile. Обновить README/canonical roadmap/sole STATUS, сохранить отчёт и логи. Никаких новых весов/API/RAG/импорта61материалов.

Контракт дополнения: option_explanations необязателен для исторических result; для новой генерации массив4 строк до500символов, объяснения на том же языке. POST attempt добавляет correct_option (текст верного ответа), feedback выбранного варианта; source_quote сохраняется. Hint API остаётся {hint:string}, модельные ограничения и статус качества фиксировать честно.
