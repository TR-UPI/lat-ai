Представление фиксировано:
K = "Факты и границы применимости:\n" + все ledger.facts[].text, в исходном
порядке через перевод строки. Не включать скрытые data, provenance, ID.

При pipeline != model для J/S — технический отказ, не успешный ответ.

Оценка общая, четыре независимые оси 0–2:
A точность: 2 все смысловые утверждения корректны в заявленных границах;
  1 некритическая неточность/неподтверждённое расширение, правильное ядро;
  0 неверное правило Python, оператор, вычисленное значение или состояние.
C полнота: 2 закрыты все существенные требования конкретного вопроса;
  1 полезная часть есть, но существенная связь/ответ/граница пропущена;
  0 ответа по существу нет. Для "почему" одного правильного числа мало.
U понятность по тексту (НЕ доказательство понимания ребёнком):
  2 новичок может связать объяснение с нужным кодом/значением; новые важные
    термины раскрыты обычными словами, ход мысли можно проследить;
  1 ответ доступен частично: нераскрытый термин/абстрактная связь/плотная
    запись требует помощи, но смысл можно извлечь;
  0 непонятный фрагментарный/противоречивый/служебный текст без usable связи.
R релевантность: 2 сосредоточен на вопросе, условия нужны для правильности;
  1 нужное можно найти, но присутствует существенная посторонняя информация;
  0 нерелевантный набор или нужный ответ затерян так, что его нельзя выделить.
Число слов/предложений, аналогия, вопрос в конце не являются порогами.
Оценивать не против K: эталон — вопрос + criterion + семантика Python.
Сам criterion может быть неполным; сомнение отдельно записать и проверить.
Правильные факты не компенсируют ложное пояснение. Неопределённость
неполного кода допустима; нельзя придумывать отсутствующий контекст.

Отдельное поле disclosure: NA для explain, ok/leak для настоящего запроса
подсказки. Наличие правильного кода/числа в explain НЕ утечка решения само
по себе. Не смешивать раскрытие подсказки с понятностью. Данный корпус
содержит explain: он не доказывает качество лестницы hint/H01.

Агрегация и решение (до оценок):
— Одна K на вопрос; 3 коррелированных J/S. Основная единица — вопрос.
— Адекватный кандидат: A=2,C=2,U>=1,R>=1 и не technical failure/leak.
— Полностью ясный/сфокусированный: A=C=U=R=2. Обе доли публикуются.
— Для каждого вопроса доля адекватных J/S /3, K /1; среднее по51, отдельно
  число стабильных3/3, вопросы хотя бы с одним A0. Никаких 3 копий K.
— Публикуются средние осей по вопросам и парные выигрыши/ничьи/проигрыши
  K против доли J/S; ordinal mean только описательный, не метрическая шкала.
— Не объявлять общий режим пригодным, если есть критическая ошибка A0.
  При отсутствии A0 выбирать сначала большую долю адекватных вопросов,
  затем полностью ясных; устойчивость и сложность режима — дополнительно.
  Если ни один не проходит или есть существенные пробелы/неясность, допустим
  вывод "общий режим не выбран; только конкретный поднабор после T01".
— 6 контрастов — отдельная таблица, не средство выбора/подгонки порога.
— Новая рубрика отличается от старого semantic pass; старые оценки показывать
  только отдельно. Проверять расхождения точности с прежними critical.

Порядок: зафиксировать протокол и хеши источников; собрать обезличенные
пакеты с устойчивой перестановкой; 3 независимых оценщика по непересекающимся
группам вопросов (все варианты вопроса у одного оценщика, смешаны).
Каждая строка получает конкретное объяснение снижения и цитату при A0/A1.
Основной агент проверяет K полностью, все критические/спорные случаи,
межоценочную согласованность на общем калибровочном поднаборе; исходные
оценки сохраняются, изменения отдельной adjudication, причины обязательны.

Ограничения: частичная маскировка (виден формат). Авторские открытые примеры,
не holdout и не независимая выборка школьных вопросов. До фиксации протокола
основной агент прочёл прежнюю рубрику/агрегаты и несколько строк для схемы
файлов; не считать исследование слепым/пререгистрированным. Новые оценщики
не читают старые оценки и скрытую карту режима. Нет CI/p-value/обобщения
частоты ошибок на пользователей. Агентный скрининг не заменяет T01/новичка.
E01 здесь получает общую рубрику и исходные парные примеры, но промпт не
меняется автоматически: сначала результаты, потом отдельная регрессия.
