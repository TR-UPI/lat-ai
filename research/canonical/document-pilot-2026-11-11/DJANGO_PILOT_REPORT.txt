Django document pilot implementation
2026-11-11

The isolated config.ai_local profile exposes the JWT document and study endpoints.
The original PostgreSQL profile and the existing Python course/assessment models
retain their separate behavior. The lesson-document endpoint filters by owner
and its serializer never returns the storage URL.

Upload validates extensions and a 20 MiB file limit. TXT is read as UTF-8,
allowing a BOM. PDF, DOCX, and PPTX load optional parsers only when selected.
Extracted text is capped at 200,000 Unicode code points. Empty/scanned,
malformed, encrypted and oversized content have explicit failure codes.
OOXML archives are checked for at most 2,048 entries and 64 MiB declared
expanded data before parser invocation. The PDF parser is configured with an
8 MiB decoded/declared stream cap, page tree and decoding work limits, and
a 1,000-page cap. Those are parser resource limits, not a sandbox. Failed
extraction records a failed item and retains neither partial text nor the
original. Accepted originals are stored privately using opaque filenames
under the isolated runtime and can only be downloaded as attachments by
their owners.

StudyPack stores an immutable excerpt with code-point bounds. A database
write lock serializes enqueue, deletion, and attempts. A conditional unique
constraint limits active jobs per owner and the shared queue is capped at
eight active jobs. Active generations block document deletion. The dispatcher
holds a process lock, records the conditional claim before dispatch, and
uses only receipts on recovery. Timeouts become unknown and are reconciled
with receipts. A receipt known to be missing or durably unknown remains
unknown. No fallback result is synthesized.

The Django validator independently rejects invalid structure, duplicate JSON
properties, nonfinite numbers, boolean answer indices, duplicate prompts or
options, and quotes missing from the exact excerpt. The study API never
serializes answer indices, hints, explanations or source quotes with unsubmitted
questions. The dedicated hint response includes the hint only. Attempt
submissions use immutable idempotency snapshots and latest-answer-per-question
progress. Source citations provide traceability. The validator cannot establish
factual accuracy or that a hint fails to reveal the answer.

Verification used an isolated test runtime and the trusted pre-existing
embedded Python plus the new parser package directory.
- 34 Django tests passed, including the 19 existing tests and 15 pilot tests.
- Actual parser fixtures covered PDF text, scanned/empty and encrypted PDF,
  DOCX paragraph and table, PPTX slide, malformed UTF-8, oversized text, and
  ZIP guard rejection before parser loading.
- Mocked IPC covered strict result validation, persisted dispatch claims,
  Windows process locking, pending receipts, recovery after a timeout,
  owner isolation, answer-key privacy and repeat-safe progress.
- A fresh file-SQLite database passed 30 threaded cases covering simultaneous
  generation for one owner, identical-request replay, and enqueue versus
  delete. Only isolated synthetic records were used.
- Live model quality and browser checks are handled by the integration run.
