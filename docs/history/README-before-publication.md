# LAT AI — LEARN AND TALK

Фронтенд учебной платформы с бесплатными школьными и университетскими курсами. Дизайн главной страницы соответствует выбранному варианту №5 «Мягкий и дружелюбный»: боковое меню, приветствие с иллюстрацией и карточки с закруглёнными углами. Палитра сочетает кремовый фон, шалфейный, лавандовый и персиковый оттенки; заголовки набраны Nunito Sans, основной текст — Inter. Карточки курсов расположены слева, документы — справа, ниже находятся ответы и блок будущего ИИ-репетитора. Основа интеграции — предоставленный Django-бэкенд; его файлы не изменялись.

Главная страница — учебный кабинет, видимый ещё до входа. До авторизации его блоки показывают пустые состояния и приглашение войти. Курсы, уроки, задания, документы и прогресс загружаются из настоящего Django API после авторизации. В папке `backend` находится копия предоставленного бэкенда без изменений его исходников. Отдельные инструменты в `tools` запускают изолированную PostgreSQL и создают учебный пример в базе; имитация API для этого режима не используется.

## Полный запуск с бэкендом и учебным примером

1. Распакуйте всю папку `LAT-AI`.
2. Откройте `START-FULL.cmd`.
3. Дождитесь сообщения `LAT AI is ready`; откроется **http://localhost:5173/**.
4. Нажмите «Войти»: почта **demo@lat-ai.local**, пароль **LatAI-Demo-2026!**.

В терминале VS Code тот же полный запуск выполняется командой `npm run full` (в PowerShell при ограничении запуска `npm` — `npm.cmd run full`).

Первый запуск требует интернета: устанавливаются локальные Python, PostgreSQL с pgvector, библиотеки и модель семантического поиска. Повторный запуск использует сохранённое окружение. Node.js нужен для фронтенда, как и в предыдущей версии проекта.

В примере: Дана, четыре курса, двенадцать уроков с заданиями, проверенные и ожидающие проверки ответы, прогресс и три загруженных учебных документа. Можно открыть урок, отправить новый ответ, загрузить свой материал и выполнить поиск. Данные сохраняются в настоящей локальной базе. Отправленный ответ имеет статус «На проверке»; оценивание доступно администратору в существующем бэкенде. ИИ-репетитор пока остаётся заглушкой исходного API.

Среда работает только на этом компьютере: фронтенд — порт 5173, Django — 8000, отдельная PostgreSQL — 55432, база `lat_ai_demo`. Запуск не создаёт службы Windows и не меняет системный PATH. База, документы, модель и локальные секреты лежат в папке окружения, а не в исходниках фронтенда. На подготовленном компьютере используется `../../work/runtime`; после новой распаковки — `.runtime` внутри проекта. Можно задать свой каталог через параметр `-RuntimeDir` у `tools/start-local.ps1`.

Демонстрационный пароль предназначен только для этого локального примера. Для подключения к вашему уже работающему API используйте «Подключение к платформе» внизу страницы; учебный пример в вашу существующую базу автоматически не переносится.

## Посмотреть дизайн

Откройте `index.html` в Edge или Chrome двойным щелчком: макет главного учебного кабинета с пустыми состояниями доступен без запуска сервера и без входа. Для авторизации и работы с реальными данными используйте запуск через HTTP, описанный ниже: адрес `file://` не подходит для штатного подключения к API с CORS.

Если окна появляются мгновенно, откройте **«Анимации» внизу страницы → «Включены» → «Сохранить»**. По умолчанию сайт следует системной настройке уменьшения движения. Выбор «Включены» разрешает плавные эффекты только в LAT AI, не меняя Windows. Настройка сохраняется отдельно в каждом браузере и для каждого адреса сайта; также доступен режим «Без движения».

## 1. Запустить фронтенд

Нужен Node.js 18 или новее с npm. Дополнительных npm-зависимостей нет, `npm install` не требуется.

1. Откройте папку `LAT-AI` в Visual Studio Code.
2. Откройте встроенный терминал и выполните `npm start`.
3. Перейдите на **http://localhost:5173**.
4. Для остановки сервера нажмите `Ctrl+C` в терминале.

В PowerShell, если запуск `npm` ограничен настройками выполнения скриптов, используйте `npm.cmd start`. Равнозначные варианты: `npm run dev` или `node server.cjs`. В Windows также можно открыть `START.cmd`.

В VS Code клавиша `F5` с конфигурацией **LAT AI in Edge** запускает локальный сервер и открывает сайт в Edge. Если сервер уже работает в другом терминале, откройте адрес вручную. При сообщении о занятом порте 5173 остановите предыдущий экземпляр.

Сервер раздаёт только локальные файлы, слушает адрес `127.0.0.1:5173`, поддерживает GET/HEAD и не выполняет серверную логику Django. Это средство локального просмотра, а не конфигурация размещения в интернете.

## 2. Подключить ваш существующий бэкенд отдельно

Этот раздел нужен, если вы используете свою рабочую базу вместо полного локального примера, описанного выше.

Используйте отдельный терминал в корне **вашего исходного Django-проекта** — там, где находятся папки `config`, `accounts`, `courses`, `documents`, `progress`, `tutor`. Не запускайте эти команды из папки фронтенда.

Бэкенду нужны его Python-окружение и зависимости из предоставленного `requirements.txt`, работающий PostgreSQL с pgvector и уже настроенная база. Используйте существующее рабочее окружение. Архивное окружение `.venv` может быть непереносимым; если оно не запускается, восстановите зависимости в отдельном окружении обычным для вашего проекта способом.

В `config/settings.py` настройки читаются из переменных окружения и `.env` в корне Django-проекта. Имена настроек: `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `MEDIA_ROOT`, `CORS_ALLOWED_ORIGINS`. Используйте свои существующие значения; пароли и секретный ключ не нужно переносить во фронтенд.

Если в проекте есть `manage.py`, выполните:

```powershell
python manage.py runserver 127.0.0.1:8000
```

В предоставленном архиве `manage.py` отсутствует. Из корня проекта можно запустить тот же Django-сервер так:

```powershell
python -m django runserver 127.0.0.1:8000 --settings=config.settings
```

Если команда `python` относится к другому окружению, используйте Python вашего рабочего окружения. Готовность сервера можно проверить по адресу **http://127.0.0.1:8000/health/**. Настройка базы и применение миграций — отдельные действия владельца бэкенда; фронтенд их не выполняет.

Для извлечения текста и семантического поиска нужны зависимости исходного проекта и модель embeddings `intfloat/multilingual-e5-small`; при первом использовании может потребоваться её загрузка.

## 3. Соединить фронтенд с API

В настройках сайта задайте базовый адрес API: **http://127.0.0.1:8000/api/v1**. Если Django работает на другом адресе, укажите его вместо примера. Затем войдите с учётной записью из вашей базы или зарегистрируйтесь.

В предоставленном `config/settings.py` значение CORS по умолчанию уже включает `http://localhost:5173` и `http://127.0.0.1:5173`. Если существующая переменная `CORS_ALLOWED_ORIGINS` переопределяет список, владелец бэкенда должен проверить, что используемый адрес фронтенда разрешён. Аналогично `ALLOWED_HOSTS` должен разрешать адрес локального Django. Файлы и настройки бэкенда в рамках этой поставки не менялись.

Ошибки соединения, CORS, авторизации и обработки документов требуют работающего существующего API. Интерфейс не заменяет недоступные серверные данные вымышленными.

## Границы текущей интеграции

- Авторизация использует JWT существующего API. Новая регистрация создаёт ученика; назначение ролей не производится публичной формой регистрации.
- Профиль в предоставленном API доступен только для чтения. Сохранение нового имени, email или пароля не заявляется как готовая функция.
- Курсы, уроки и упражнения читаются из API. Полноценное управление курсами преподавателем требует отдельного развития бэкенда.
- Документы: PDF, DOCX, PPTX и TXT до 20 МБ; загрузка, статусы обработки, удаление и поиск фрагментов по содержимому. API фильтрует документы по владельцу. При этом исходный Django раздаёт файлы по `/media/` напрямую; этот механизм не изменён, отдельная защита доступа к самим файлам здесь не добавлялась. Название берётся из имени файла. Папки, совместный доступ и OCR сканов не заявляются.
- Проверка ответов ограничена правами `is_staff` в бэкенде. Одного значения роли `teacher` недостаточно. Сам интерфейс не может выдать такие права. Панель проверки преподавателя не создана: в предоставленном API нет списка всех ученических попыток для такой панели.
- ИИ-репетитор пока запланирован: `/tutor/ask/` возвращает `501 Not Implemented`, полноценного ИИ-ответа и подключённой LLM нет. Семантический поиск по документам — отдельная уже предусмотренная возможность.
- Показ бесплатных курсов — продуктовая концепция интерфейса. Оплата и подписки в этот прототип не входят.

## Файлы

Анимации: мягкое нажатие и волна на кнопках, плавное перемещение выделения меню, появление разделов и карточек, заполнение полос прогресса, открытие форм и индикатор отправки. В режиме «Как в системе» эффекты следуют системной настройке уменьшения движения; в настройке «Анимации» можно явно включить их только для сайта.

- `index.html` — страница приложения.
- `assets/motion.css`, `assets/motion.js` — анимации и отклик интерфейса на действия.
- `assets/styles.css`, `assets/friendly.css`, `assets/app.js`, `assets/data.js`, `assets/fonts.css` — стили, логика, вспомогательные данные и подключение шрифтов; тестовая база данных не включена.
- `assets/study-illustration.png` — иллюстрация, созданная встроенным imagegen по выбранному макету; запрос сохранён в `assets/illustration-prompt.txt`.
- `server.cjs` — локальный статический сервер без сторонних зависимостей.
- `package.json` — команды запуска.
- `.vscode/` — задача запуска и конфигурация Edge.
- `START.cmd` — запуск в Windows.
- `START-FULL.cmd` — полный локальный запуск с Django, PostgreSQL, моделью поиска и учебными данными.
- `backend/` — неизменённый исходный Django-проект.
- `tools/` — установка локального окружения, запуск, заполнение отдельной учебной базы и проверка API.

Это локальная сборка фронтенда и предоставленного Django, проверенная на отдельной базе с учебными данными. Публичное размещение не выполнялось; ваша существующая рабочая база не затрагивалась.
