# I02.2 — минимальная сквозная интеграция

Основание: пользователь прямо поручил подключить каркас для ручной проверки 10.11.2026. Контракт I02.1 остаётся спецификацией; повторное согласование выбранной связки не требуется.

Схема: существующий браузер → Django JWT и проверка опубликованных ресурсов → приватный локальный Node worker → неизменный Tutor v10 → явный источник ответа. Один worker владеет координатором модели и постоянным журналом replay/выданных подсказок. Браузер не получает IPC-секрет и не обращается к модели напрямую.

Ruling: для локальной проверки использовать отдельные настройки того же Django и SQLite, без запуска документов/RAG. Основные настройки PostgreSQL и его данные не меняются. Причина: общий установщик тянет ненужные веса и инфраструктуру. Ограничение: этот запуск не доказывает работу производственной конфигурации PostgreSQL.

Ruling: журнал ИИ в приватной SQLite worker, сервер передаёт только проверенные попытки. Worker сериализует подсказки и читает собственную историю внутри секции. Существующий progress не изменяется ИИ. Незавершённый запрос после аварии не отправляется повторно; возвращается 503. Нужна повторная проверка доступа перед каждым replay.

Ruling: mapping создаётся явно для изолированных учебных примеров и привязан к хешам содержания, не угадывается по ID/названию. Упражнения из сторонней БД требуют своего проверенного mapping. Полные решения и ученический допуск не включаются.

- [x] 1. RED→GREEN: persistent bridge, replay/conflict/restart, доверенная лестница и конкурентные запросы. Сохранить логи.
- [x] 2. RED→GREEN: Django JWT/access/mapping, ограничения и безопасный IPC. Изолированный профиль и примеры без фиктивных проверенных попыток.
- [x] 3. RED→GREEN: редактор на странице задания, снимок/выделение до await, простой вопрос, source/facts/errors, stale и повтор того же ID.
- [x] 4. Сквозные HTTP и браузерные проверки, установленная локальная модель, резерв и два клиента. Независимое ревью, исправления, итоговые регрессии.
- [x] 5. Инструкция запуска, пакет без runtime/секретов, отчёт, единственный STATUS и roadmap.

Проверка завершения: новый каркас открыт на ноутбуке, можно вручную спросить по коду и выделению. Не считать ответы резервом измерением качества модели. Логи не содержат JWT, IPC-секрет, вопрос или код. Сохраняются старые v10/v4 и архив I02.1.

Review focus: повтор после потери HTTP, авария между моделью и commit, чужой actor, доступ после распубликации, изменение mapping, выдача приватных файлов, Unicode и stale, отсутствие автоповтора генерации, неизвестная модельная операция после перезапуска.
