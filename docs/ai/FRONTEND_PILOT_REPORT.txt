Task 3 | Document pilot frontend

Changes in assets/app.js, assets/data.js and assets/styles.css. Added tests/document-pilot-frontend.test.cjs.

The Documents page lists uploaded documents, private mini-courses and tests, job state, and per-pack progress. Upload opens the document preview. The detail view exposes manual 1-based inclusive boundaries and text selection. It previews the exact excerpt, converts boundaries to zero-based end-exclusive Unicode code-point offsets, and requires 100–6000 code points. Documents within that range default to the whole source. Longer documents default to their first 6000 code points with the exact bounds visible. The pilot replaces the semantic search controls.

Study opens by saved pack ID, polls queued/running/unknown jobs via GET, and stops when the job is ready/failed or navigation removes the view. Failed generation has no test or grade. Ready courses show lessons and their quotes. Tests show single-choice options, explicit hint requests, automatic scoring by model-authored keys, feedback and source quotes after submission, and the current aggregate progress. Model/document text is rendered as escaped HTML or assigned to textContent. The question template excludes answer keys and pre-submission question quotes.

Generation and attempt POSTs use a UUID scoped to account, API, resource and request parameters. An ambiguous response keeps the ID in browser session storage (memory fallback). Repeating the same submission reuses it. Generation polling never issues another POST. An uncertain grading response produces no grade display. Original Python tutor code and grading request paths were kept.
